# 戦術実行ログ監査（2026-10-05）

## 結論

デイトレード・スイング・中期投資が、サイト内で掲げる時間軸どおりに執行されていたとは認められない。TP/SLと反転判定など一部の価格条件は実装されているが、戦術ごとの足種と最大保有バー数は執行コードで使われていない。以下の件数は監査中にも稼働サーバーが追加記録しているため、監査時点の値として扱う。

## 監査方法

- `data/invest_history.db` の `trades` を口座・銘柄・出所別に集計し、`opened_at` と `closed_at` から保有時間を算出。
- `ai_decisions` の BUY/SELL/CLOSE 理由文と銘柄・時刻を照合して戦術を推定。戦術列と取引ID結合キーが存在しないため、厳密なトレード単位の証明はできない。
- `STRATEGY_PROFILES` と `evaluate_and_execute`、`generate_race_card`、市場ティックを照合。

## 主な実測結果

| 口座・戦術 | 決済 | 実際の保有時間 | 判定 |
|---|---:|---|---|
| 公式AI・スイング | 438件 | 中央値51.7秒、412件が1分未満、最長約41分 | 「数日～数週間」と不一致 |
| 田中・スイング | 理由ログと一意対応した17件 | 中央値約46秒 | 「数日～数週間」と不一致 |
| 田中・中期 | 理由ログと一意対応した2件 | 最長約47秒 | 「数週間～数か月」と不一致 |
| スズキ・デイトレ | 理由ログと一意対応した53件 | 中央値約60秒、最長約177秒 | 短時間決済だが15分足・当日運用の実証にならない |
| guest・デイトレ | 3件 | 約29.3、42.2、49.8時間 | 当日内決済と不一致 |
| 長期投資 | 0件 | 評価不能 | 実績なし |

公式AIの438件は決済理由ログにすべて「スイングトレード」と記録され、純損益は合計 -2,645,924.43円。内訳はBTC-USD 126件、USDJPY=X 312件。これらは仮想価格でのペーパートレードであり、実市場の約定実績ではない。

## コードとログの照合

1. `src/invest_engine/autopilot_engine.py` の `default_interval` と `max_holding_bars` は戦術定義にあるが、売買判定で参照されない。デイトレの15分足・最大4時間、スイングの1時間足・40バーは強制されない。
2. `src/invest_engine/game_manager.py` は全戦術で2年分の日足を使って翌日予測を作る。市場ティックは約3秒ごとで、実価格アンカー付近に乱数で作った価格で評価・約定する。市場休場時の執行停止判定はない。
3. `cooldown_ticks` はバーではなく全銘柄を通じた評価呼び出し回数で進む。デイトレ6、スイング20という値は想定した時間待機にならない。
4. TP/SL価格、反転決済（スキャル・デイトレのみ）、期待値フィルターはコードにある。ただし各取引に当時の入力値が保存されておらず、個々の判断が全条件を満たしたか再計算できない。
5. `ai_decisions` は約130万件あるが、`prob_up`、`regime`、`htf_trend`、`meta_bet_size`、`features_json` は空で、`trades` と結ぶ戦術・注文・取引IDもない。旧実装では田中・スズキ・guestの自動取引も `USER` に分類されている。

## 次に直す順序

1. 口座ごとに戦術、足種、バー確定時刻、注文ID、建玉ID、決済理由、入力特徴量を記録する。
2. 戦術別の確定バーでのみ評価し、最大保有バー数と当日内決済を実装する。休場時は約定を停止する。
3. 模擬ティック価格と実市場データの用途を分け、画面にも明示する。
4. 保存した判断入力から、各取引のエントリー・エグジットを再実行して一致を検証する。
