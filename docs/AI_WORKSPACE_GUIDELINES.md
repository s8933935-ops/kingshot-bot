# AI Workspace & Directory Management Guidelines
（AIのためのフォルダ・ファイル作成＆管理憲章）

本ガイドラインは、AIエージェント（Antigravity, Claude, Qwen等）および開発者が本ワークスペース内で作業する際に、**探索効率の最大化、コンテキスト（トークン）の節約、およびハルシネーション（誤認・誤参照）の撲滅**を達成するために策定された厳格な運用ルールです。

---

## 1. 3大コア原則（シロクマ式フォルダ管理術）

### 原則①: 分類基準の単一化（Single Classification Axis）
* 第1階層（ルート直下）のフォルダは、**「資産のライフサイクルと役割」**という単一の基準でのみ分類する。
* 「人別」「案件別」「日付別」が同一階層で混在することを禁止する。

### 原則②: プレフィックスによる先頭情報の明示（Leading Sortable Keys）
* PCやAIツールはファイルを名前順（アルファベット・数字順）で走査する。
* **時系列ログ・議事録**: `YYYYMMDD_概要.md` のように先頭に8桁の日付を付与。
* **ステップ・パイプライン**: `01_extract.py`, `02_transform.py`, `03_load.py` のように2桁連番を付与。

### 原則③: SSOT（信頼できる唯一の情報源）の徹底と世代管理
* `app_final.js`, `main_v2_fix.py` のような曖昧なバージョン管理ファイルを作成してはならない。
* バージョン管理は Git のコミット履歴に委ねる。
* 過去の遺産を一時退避する場合は、必ず `archive/YYYYMM/` フォルダへ隔離する。

## 2. 標準ディレクトリ構成（Standard Layout）

AIが新規ファイルやフォルダを作成する場合、必ず以下のカテゴリに従って配置しなければならない。

```text
multi-agent-designer/
├── src/                    # 【本番稼働コード】常駐プロセス、API、コアモジュール
│   ├── bot/                # Satisfactory Bot (Python)
│   ├── sgr_bot/            # SGR / Discord Controller (Node.js)
│   ├── rag/                # 検索エンジン・RAGロジック
│   └── utils/              # 共通ユーティリティ
├── scripts/                # 【単発実行・ツール】
│   ├── maintenance/        # 診断・チェック用スクリプト
│   └── tools/              # データ生成・スクレイピング・ビルドスクリプト
├── tests/                  # 【テストコード】単体テスト・結合テスト
│   ├── unit/
│   └── integration/
├── docs/                   # 【ドキュメント・仕様】
│   ├── ai_reports/         # AI作戦会議ログ、評価レポート
│   ├── guides/             # ユーザーマニュアル、運用手順書
│   └── archive/            # 古い仕様書や過去のタスク計画
├── web_apps/               # 【Web UI・フロントエンド資産】
│   ├── tierlist/
│   ├── nuclear_dashboard/
│   └── scheduler/
├── scratch/                # 【AI専用サンドボックス】一時スクリプト・中間データ (Git除外)
└── archive/                # 【過去資材の退避場所】
```

## 3. AIエージェントへの禁止事項（Guardrails）

1. **ルート直下への無断ファイル作成禁止（No Root Pollution）**:
   * 設定ファイル（`.env`, `.gitignore`, `package.json` 等）およびプロジェクト設定・憲章（`README.md`, `AGENTS.md`, `GEMINI.md`）を除き、**ルート直下に新しいスクリプトや markdown ファイルを直接作成してはならない**。
2. **一時検証コードの放置禁止**:
   * 動作確認やデバッグ用のスクリプトは、必ず `scratch/` ディレクトリ内に作成し、検証完了後は速やかに削除または整理する。
3. **無差別な大量ファイル生成の禁止**:
   * スクレイピングや画像切り出し等の処理を行う場合は、必ず専用の出力サブディレクトリ（例: `data/output/YYYYMMDD/`）を指定して生成し、ルートや親ディレクトリを散らかさない。

## 4. フォルダ作成・変更時の必須ステップ

AIが新しいフォルダやモジュールを作成する際は、以下のステップを踏むこと。

1. **配置先の妥当性確認**: 上記の標準ディレクトリ構成に合致しているか確認する。
2. **README.md / index.md の配置**: 新規フォルダを作成した場合、そのフォルダの「目的」「含まれるファイル」「更新日」を記した簡潔な `README.md` を作成する。
3. **参照パスの整合性確認**: 移動・リネームを行った場合は、依存する `require` や `import` パスを即座に走査して追従修正し、テストを実行して整合性を検証する。
