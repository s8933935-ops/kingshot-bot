# 📘 KingShot プロジェクト「近畿成功マニュアル（開発ルールブック）」

**発行責任者**: 習熟・品質向上部門（Mastery & Continuous Improvement Lead）  
**適用対象**: 親エージェント（PM）、設計部、開発・エンジニアリング部、動作確認・QA部、全サブエージェント  
**目的**: 過去の全デバッグ履歴・事故・エラーから得られた失敗パターンを絶対ルール化し、未検証コードの納品およびユーザー様への検証負担の発生を永久に根絶する。

## 1. 開発フロー＆品質保証（QA）ルール

### 1-1. 物理DOM＆キャッシュの強制リセット原則
- **[事故背景]**: PCブラウザ（Chrome/Edge等）では、JSで `localStorage.clear()` や `this.stats = []` を行うだけでは、HTMLの `<input type="number">` や `<select>` の表示値がブラウザキャッシュ機能により保持され続け、「初期化ボタンを押しても数値が消えない」現象が多発した。
- **[Strictルール]**:
  1. ステートのリセット（データ消去）を行う処理を実装する際は、**必ず画面上のすべてのフォーム要素（HTML DOM）の値をコード上で物理的に書き換えるロジックを強制記述**する。
     ```javascript
     // ✅ 必須記述形式
     document.getElementById('fighterNameInput').value = "";
     document.querySelectorAll('select').forEach(el => el.selectedIndex = 0);
     document.querySelectorAll('input[type="number"]').forEach(el => el.value = "0");
     ```
  2. メモリ上データ・`localStorage`・DOM表示の **3点の同期** を関数完了時に必ず検証する。

### 1-2. ゼロ・モック・ポリシー（Zero-Mock Policy）
- **[事故背景]**: 開発の初期・中盤において、画像読み込みやOCRの挙動確認にファイル名・サイズの疑似ハッシュや `Math.random()` によるダミー値を割り当てたため、「画像を変えても数字が変わらない」「数値の精度が著しく低下する」という不具合が連続発生した。
- **[Strictルール]**:
  1. プロダクションコードおよび検証用コードにおいて、**疑似ハッシュ・ダミー乱数・仮置きのフォールバック値（例: `|| 923`）の記述を完全禁止**とする。
  2. 本物のAPI・AIライブラリ（`Tesseract.js`等）が未読み込みの状況であっても、モック数値を画面に反映させてはならない。未処理の場合は明確に「未解析（0.0%）」と表示する。

### 1-3. クロスデバイス（PC / モバイル）両系検証義務
- **[事故背景]**: スマホ表示枠（`previewContainer`）の中にリセットボタンを配置したため、スマホでは機能してもPC画面ではボタンが非表示になり、PCユーザーがリセット操作を行えなくなった。
- **[Strictルール]**:
  1. 全画面共通の操作ボタン（リセット・保存・切り替え）は、**特定のコンテナ（`hidden` クラスが付与され得る枠）の外部に配置**する。
  2. 納品前の確認は、必ず「PCデスクトップ表示」と「モバイルレスポンシブ表示」の **両方の表示状態においてクリック・イベント発火テストをパス** させること。

## 2. 実装＆コーディング規範（JavaScript & HTML）

### 2-1. ハードコード・フォールバックの禁止
- **[事故背景]**: `app.js` の `authenticSchema` にて `"defense": Math.round(getVal('inf_def') || 923)` というフォールバックコードが残留していたため、ユーザーがデータを `0` にリセットしても、出力されるJSONには常に `923` が強制代入される致命的バグが発生した。
- **[Strictルール]**:
  1. 値が未設定または `0` の場合、OR演算子（`||`）による**デフォルト数値代入を厳禁**とする。
     ```javascript
     // ❌ 禁止
     const def = getVal('inf_def') || 923;

     // ✅ 必須（Strict判定）
     const rawVal = getVal('inf_def');
     const def = (typeof rawVal === 'number' && !isNaN(rawVal)) ? Math.round(rawVal) : 0;
     ```
  2. マスタデータ（例: 英雄31名のIDリスト）は定数ファイルに完全固定し、アルファベットの小文字表記（`petra`, `alcar`）を型として一貫保持する。

### 2-2. 高精度OCRパースパターン（Tesseract.js）
- **[事故背景]**: 全画面の画像に対して `\d+`（汎用数値抽出）をかけたため、ヘッダーの戦力・プレイヤーレベル・日付などの無関係な数字をステータス数値として誤抽出した。また、過度な二値化（`avg > 120`）で金文字ドットが破壊された。
- **[Strictルール]**:
  1. 画像の二値化処理を行う際は、輝度演算（Luma: `0.299*R + 0.587*G + 0.114*B`）を維持し、文字色（金・白・緑）のコントラストを破壊しない。
  2. 数値抽出の正規表現は、**パーセント記号付きパターンに特定**する。
     ```javascript
     // ✅ 必須抽出正規表現
     const statPattern = /[+＋]?\s*(\d{2,4}(?:\.\d)?)\s*[%％]?/g;
     ```
  3. 抽出された値は `50.0` 〜 `3000.0` の有効範囲フィルタを通し、外れ値を自動排除する。

## 3. ドメイン知識＆仕様固定マニュアル（KingShot特有）

### 3-1. 兵数（Troop Quantities）設定の非介入原則
- **[仕様根拠]**: ユーザー様からの直接指示・物理検証より。「出撃兵数を任意入力させると、本家シミュレーターの黄金比率（最適フォーメーション）を導き出す計算の妨げ・歪みになる」。
- **[Strictルール]**:
  1. 画面上に兵隊の「数量（数量入力ボックス）」を追加してはならない。
  2. JSON出力における兵数ベース値は、本家テンプレートの推奨固定数値を厳格保持する。
     - 歩兵（Infantry）: `85326`
     - 槍兵（Lancer）: `14221`
     - 弓兵（Marksman）: `5000`

### 3-2. スイッチ＆トグル操作の注意事項（ユーザー案内）
- **[仕様根拠]**: 本家サイト（`kingshotsimulator.com`）にJSONをインポートした際、本家UIの「Heroes Stats are included here ?」トグルがグレー（OFF）のまま見えても、内部データには `"stats_include_heroes": true` が正しくセットされている。
- **[Strictルール]**:
  1. 本家サイト側でユーザーが手動でトグルをONに変更すると、英雄ステータスが2重加算されて計算が壊れるため、UI上に**「本家サイトでトグルに触らないこと」という注意書き警告ボックスを常時設置**する。
  2. Joiner（乗り手）は本家サイトの仕様上、インポート後に「Joiners」タブを開いて確認する必要がある旨をガイドに明記する。

## 5. モデルルーティング＆エージェントリソース最適化規範

### 5-1. 単一最上位モデル運用の原則禁止（適材適所ルーティング）
- **[事故/非効率背景]**: すべてのサブエージェントやパイプライン処理に最重量・高コストモデル（Tier 3）を一律割り当てると、単純なWeb検索やJSON整形・タグ付けで無駄な待ち時間（数秒〜十数秒）とトークン浪費が発生する。
- **[Strictルール]**:
  1. サブエージェント起動時（`invoke_subagent`）は、**タスクの複雑度に応じた最小十分モデル（Tier 1〜3）を明示的に指定**する。
     - **Tier 1 (軽量高速 / `flash` or `flash_lite`)**: Web検索、データパース、正規表現テスト、JSONバリデーション、初期フィルタリング
     - **Tier 2 (実務主力 / `pro`)**: ガイドドキュメント執筆、OCR構造化、デザインレイアウト設計
     - **Tier 3 (高度推論 / `pro` 推論モード)**: 中心極限定理等の統計数理証明、複雑なメタ相性計算、全体オーケストレーション
  2. 単純なデータ取得・整形タスクに Tier 3 モデルを単独割り当てすることを禁止する。

## 6. ゴージャス・インフォグラフィック＆メディア制作規範

### 6-1. プレーンテキスト/簡易HTML出力の禁止（リッチメディア義務化）
- **[事故/不満背景]**: テキストとCSSの色分けだけの簡素なHTMLを出力すると、ゲーム攻略記事としての魅力・ゴージャス感・没入感が著しく低下し、ユーザー様およびクランメンバーの満足度を損なう。
- **[Strictルール]**:
  1. メディア制作部（HTMLインフォグラフィック出力）は、**必ずAI画像生成（`generate_image`）を活用し、キービジュアル・ステージ背景・宝箱報酬などの高解像度美麗アート（16:9 / ゲームアート調）を複数枚自律生成して組み込む**。
  2. レイアウトは **Tailwind CSS ＋ グラスモフィズム（高級感あるパープル/ゴールド/エメラルド発光） ＋ Chart.js（インタラクティブ円グラフ/棒グラフ） ＋ レスポンシブカードUI** を標準装備とする。
  3. 生成されたHTMLファイルおよび画像アセットは、直ちに `C:\Users\s8933\Downloads\` に配置し、ブラウザで即座にフルビューできるようにする。

## 7. 事故防止・トラブルシューティングチェックリスト

開発完了・コード変更時、QAチームは以下のチェックボックスを**全てパス（YES）**しない限り、ユーザー様へ成果物を報告・納品してはならない。

- [ ] **[Check 1] DOM物理リセット確認**: リセットボタンを押した際、`localStorage` が空になり、なおかつ画面上の全 `<input>` / `<select>` の値が物理的に初期化（0またはデフォルト）されるか？
- [ ] **[Check 2] JSON出力のゼロ一致確認**: リセット状態のままJSONを出力した際、`stats` 内の各数値が `0`（または未設定）であり、`923` などの固定数値が残っていないか？
- [ ] **[Check 3] 画像変更時のリアル更新確認**: 異なる2枚のスクショを読み込ませた際、ハッシュやダミーではなく、画像の実際の％数値が正しく抽出されて画面に反映されるか？
- [ ] **[Check 4] PC/スマホ両系UI表示確認**: 横幅1920px（PC）と横幅375px（スマホ）の両サイズで、リセットボタンやダウンロードボタンが押し切れる位置に常時表示されているか？
- [ ] **[Check 5] 兵数入力フィールド不在確認**: UI上に兵隊の数量入力ボックスが存在せず、最適フォーメーション計算を妨げない構造になっているか？
- [ ] **[Check 6] モデルルーティング適合確認**: サブエージェント呼び出し時に適切なTier（Tier 1: Flash / Tier 2: Pro / Tier 3: 推論特化）が割り当てられ、無駄な待ち時間・コストが発生していないか？
- [ ] **[Check 7] リッチグラフィック＆挿絵充足確認**: HTML記事において、AI生成された高品質キービジュアル・背景イラスト・グラフがふんだんに配置され、十分なゴージャス感・ゲーム没入感が担保されているか？
