# Satisfactory Discord RAG Bot 品質改善チーム作業計画

## 目的

生産メタ拡充後のBotについて、実際の自然言語入力に対する挙動を確認する。
特に、計算値の正確性、存在しない素材の捏造防止、文脈継承、難易度ルーティング、
副産物処理の説明が、既存アーキテクチャの設計どおり動作することを検証する。

## 品質改善チーム編成

### 1. テスト設計担当

- テストケースと期待結果を定義する。
- 日本語・英語・全角数字・曖昧な指示語を含む入力を準備する。
- 仕様上の「正しい回答」と「許容しない回答」を明文化する。

### 2. 確定計算検証担当

- `calculator.py` の計算結果を検証する。
- 機械台数、毎分レート、副産物、発電量を手計算またはレシピDBと突合する。
- LLMが計算した値を採用していないことを確認する。

### 3. RAG・グラウンディング検証担当

- `production_metas.json` と `recipes.json` から根拠が取得されるか確認する。
- 存在しない素材、架空レシピ、誤った代替レシピが回答に混入しないか検証する。
- 「DBに存在しない」場合に、Botが不明と明示できるか確認する。

### 4. ルーティング・会話文脈検証担当

- GPT-4o-mini／Claudeルーティングの発動条件を確認する。
- 通常質問、比較質問、大規模工場設計、画像・診断系質問を分類する。
- `current_topic` と直前レートが、次の質問へ正しく継承されるか確認する。

### 5. Discord UX・回帰テスト担当

- Discordカード、エラー表示、モデル名フッター、利用上限表示を確認する。
- 既存テストを毎回実行し、変更による回帰を検出する。
- 実機テストで発生した入力と応答を再現テストへ追加する。

## 検証フェーズ

### Phase 1: ローカル決定論テスト

対象:

- `tests/test_agent_reasoning.py`
- `tests/test_context_and_comparison.py`
- `data/processed/production_metas.json`
- `data/processed/recipes.json`

確認項目:

1. ロケット燃料の通常／代替レシピが区別される。
2. イオン化燃料のロケット燃料・パワーシャード投入量が正しい。
3. プルトニウム燃料棒の生産レートが正しい。
4. 廃棄物ゼロ方針が「燃焼」ではなく「FICSITシンク」で説明される。
5. 全角数字、単位省略、英語名、日本語名を処理できる。

### Phase 2: 反ハルシネーションテスト

入力例:

- `ロケット燃料を毎分150作るには？`
- `イオン化燃料の材料を教えて`
- `存在しない燃料「超音速燃料」のレシピは？`
- `プルトニウム廃棄物を原子炉で燃やせば完全に消える？`
- `窒素ガスだけでロケット燃料を作れる？`

合格基準:

- DBにないレシピを断定しない。
- 「燃料」と「ターボ燃料」を混同しない。
- 副産物を省略しない。
- 不明な値は不明と明示し、推測値を確定値として出力しない。

### Phase 3: 文脈・ルーティングテスト

会話例:

1. `原油480で希釈燃料を計算して`
2. `これをロケット燃料にするには？`
3. `代替レシピと比べて`

確認項目:

- `480/分` の文脈が維持される。
- 「これ」が直前の対象を指す。
- 比較質問で高難度ルーティングが発動する。
- 最終回答には確定計算結果と根拠レシピが含まれる。

### Phase 4: Discord実機スモークテスト

実施順:

1. `/recipe ロケット燃料`
2. Botメンションによる自然言語質問
3. 直前質問を参照するフォローアップ
4. 不正・空入力
5. Claude利用上限到達時のフォールバック

記録するもの:

- 入力全文
- 選択されたルート／モデル
- calculator実行の有無
- RAG根拠の有無
- 最終回答
- エラー・再接続・応答時間

## 合格判定

次の条件をすべて満たした時点で品質改善フェーズ完了とする。

- 既存テストが100%合格する。
- 新規メタ4項目がRAGから取得できる。
- 計算値がレシピDBの毎分レートと一致する。
- 架空素材・架空レシピを断定しない。
- 文脈継承テストが成功する。
- Discord実機で代表5ケースが正常応答する。
- 失敗ケースが再現テストとして保存される。

## 実行コマンド

```powershell
python tests/test_agent_reasoning.py
python tests/test_context_and_comparison.py
```

実機確認前に、Botの起動状態と `bot.log` の末尾20行を確認する。

## 次の着手順

1. Phase 1の新規メタ検証テストを追加する。
2. Phase 2の反ハルシネーション入力を自動テスト化する。
3. ローカルテスト合格後にDiscord実機スモークテストを行う。
4. 失敗があれば、まず根拠データ・ルーティング・プロンプトのどの層かを分類する。
5. 修正後に全回帰テストを実行する。
